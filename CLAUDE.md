# CLAUDE.md — osb-ship-scenario

Vite + React 19 + TypeScript strict SPA. React Router 7 (`react-router`, declarative), PixiJS 8, Tailwind 4 with shadcn/ui, Vitest + React Testing Library.

## Commands

```bash
npm run dev
npm test
npm run build        # tsc -b && vite build; type errors fail the build
npm run record-game -- <espnEventId>
```

## Architecture (keep these boundaries)

- `features/gameplay/engine/` is pure TypeScript. No React, no pixi.js imports. `reduce(state, event)` is deterministic; mapping constants live in `mapping.ts`.
- `features/gameplay/feeds/` produce `GameEvent`s. Any new data source (OSB socket diff, balldontlie play-by-play) is a new `createXxxFeed` here that implements `Feed`. No React, no pixi.js.
- `features/gameplay/renderer/` owns Pixi. `ScenarioRenderer` implements `RendererPort`; animations drain through `ActionQueue` one at a time. The renderer owns its canvas (`mount(host)`), and `ScenarioCanvas` lazy-imports it so Pixi never loads on the setup route or in jsdom. Sprite art under `public/sprites/` is generated for this project (see `CREDITS.md` there for provenance and the facing-up/facing-down orientation rule); manifest in `renderer/spriteManifest.ts`, loaded by `assets.ts`. The explosion is a frame strip sliced in `world.ts` (`stripFrames`) and stepped by `burst()`. Enemies live in a `SquadronModel` (pure, tested) rendered by `SquadronView`; animations take members from it rather than spawning. Presentation pass: `renderer/quality.ts` picks `high` or `low` (auto-detected, `?quality=high|low` overrides) and gates effects. `renderer/fx.ts` (math in pure `fxMath.ts`) holds bloom, glow, trails, screen shake and the white flash (`pixi-filters`). `world.ts` layer order, back to front: backdrop, farStars, farRocks, nearStars, nearRocks, enemyLane, shipLayer, effects, overlay (low-hull vignette). The backdrop (`backdrop.ts`) is OSB's galaxy image, cover-fit and slowly panned. Every action can carry a `caption` (set by the feed as `label`); `renderer/callout.ts` floats it at the action for 1.5 s without blocking the queue.
- `features/gameplay/hooks/useScenario.ts` is the only bridge between feed, engine and renderer.
- Routes live in `src/app/router.tsx`. New OSB screens go under `src/features/<name>/` and get a sibling route.

## Conventions

- shadcn primitives via `npx shadcn@latest add <component>`; never edit `src/components/ui/*` by hand.
- `PascalCase.tsx` components, `camelCase.ts` everything else, `@/` alias for cross-feature imports.
- Tests: Vitest; engine and feeds are unit-tested, renderer is checked manually through `DebugPanel` (dev only).
- Fixtures are generated by `scripts/record-game.ts`; ESPN's format never leaks past that script.
